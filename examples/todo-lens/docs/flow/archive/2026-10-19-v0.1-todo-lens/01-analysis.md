# 01 需求分析：TODO Lens

## 一句话目标
在 VS Code 侧边栏集中查看并快速跳转到工作区里的 TODO / FIXME 注释。

## 用户故事
- US-1 作为开发者，我想在一个列表里看到所有 TODO/FIXME（按文件分组），以便掌握待办全貌。
- US-2 作为开发者，我想点击某一条就跳到代码对应的行，以便马上处理。
- US-3 作为开发者，我想在状态栏一眼看到 TODO 总数，以便感知技术债的变化。
- US-4 作为开发者，我想自定义关键字（例如加上 HACK），以便适配团队的约定。

## 范围
**范围内**
- 扫描工作区文本文件中**注释里**的关键字（`//`、`#`、`/* */`、`*`、`<!-- -->`、`--`）
- 侧边栏树视图：文件 → 条目；状态栏计数；保存后增量刷新；可配置关键字、排除 glob、文件数上限
**范围外**
- 完整的语言级注释解析（字符串里的 `// TODO` 允许误报）
- 优先级、负责人、截止日期等元数据；导出或同步到 Issue
- 多根工作区的分组展示（只合并展示）；Webview 界面

## 验收标准
| 编号 | 关联故事 | 标准 |
|---|---|---|
| AC-1 | US-1 | Given 工作区含 TODO/FIXME 注释 When 工作区打开，或执行"TODO Lens: 重新扫描" Then 视图按文件分组列出全部条目，每条显示关键字、说明和行号 |
| AC-2 | US-2 | Given 列表中有条目 When 点击该条目 Then 打开对应文件，光标定位到该行的关键字处 |
| AC-3 | US-3 | 状态栏显示 `$(checklist) N`，N 与列表条目总数一致；点击后打开该视图 |
| AC-4 | US-1 | Given 已完成扫描 When 保存某个文件 Then 1 秒内该文件的条目和总数更新，不做全量重扫 |
| AC-5 | US-4 | 修改 `todoLens.keywords` 后自动重扫并按新关键字生效；关键字匹配逻辑有单元测试 |
| AC-6 | US-1 | 没有结果时视图显示欢迎文案和"重新扫描"链接；文件数达到上限时弹出提示，说明结果可能不完整 |

## 约束
- `engines.vscode` ≥ 1.95；零运行时依赖；TypeScript strict
- 隐私：只在本地读取文件，不联网
- 性能：约 2000 个文件的仓库，首次扫描应在 3 秒内完成（参考值）

## 风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| 大仓库扫描慢或占内存 | 卡顿 | 默认排除 node_modules/dist/out/.git，并设置 maxFiles 上限 |
| 正则误报（字符串中的 `// TODO`） | 列表有噪声 | 接受，已写入范围外 |

## 开放问题（附默认建议）
1. Q：是否区分大小写？→ 默认：区分（只匹配 `TODO`，不匹配 `todo`）
2. Q：未保存的修改是否实时更新？→ 默认：否，只在保存时更新（AC-4）
